# Collection·사내 취약점 DB Docker 검증

2026-10-18, 운영 자료가 없는 격리 Docker 샘플로 검증했습니다. 기존 PostgreSQL 볼륨을
유지한 업그레이드 경로이며 기존 분석·정책·Grype DB를 함께 사용했습니다.

## 구현

| 기능 | 처리 방식 |
| --- | --- |
| 부모 Collection | 직접 자식, 최신 표시 자식, 특정 태그 자식, 전체 하위 프로젝트 선택. 중첩 Collection 설정, 비활성/보관 제외, 동일 회차 중복 합산 방지 |
| 집계 근거 | 자식별 최신 비보관 회차의 완료 분석 ID·리비전과 미분석/오래된 결과/정책 미완료 커버리지 제공 |
| 지표 | 구성요소·취약 구성요소·취약점 발생·고유 취약점 ID·심각도·KEV·정책 결과·VEX 억제 |
| 사내 DB | 내부/CVE ID와 제목·설명·심각도·CVSS·CWE·별칭·참고 URL·영향 PURL/버전·수정 버전 작성 |
| 관리 | 초안·게시·철회, 낙관적 동시 수정 보호, 작성 이력·감사 로그, 물리 삭제 대신 철회 |
| 분석 반영 | 게시된 사내 DB와 실제 Grype 분석을 함께 사용. 영향 회차의 자동 재분석, 내부 ID 발견 표시·정책·VEX·Collection 반영 |
| 증거 보존 | 분석별 게시 항목의 작성 리비전·해시, 불변 작성 이력. 철회해도 과거 분석은 보존 |

일반 관리자 화면에서 Collection 설정·집계와 사내 DB 작성·게시·철회·이력을 사용할 수 있습니다.
구체적인 API와 권한, 범위 판정 규칙은 [운영 문서](operations-ko.md#collection-집계와-사내-취약점-db)를 참조합니다.

## 실제 샘플 결과

Grype 0.109.1과 2026-10-10 데이터 번들을 사용했습니다. 외부 분석 서버 연결은 비활성이고
8개 자체 서비스로 실행했습니다. 샘플은 두 버전 자식 각각 공개 패키지 2개와 사내 패키지 1개입니다.

| 확인 항목 | 관측 결과 |
| --- | --- |
| 직접 자식 | 2개 프로젝트, 구성요소 6개, 취약점 발생 18건, 고유 취약점 ID 13개 |
| 최신 표시 자식 | 2.0.0 자식만 선택, 구성요소 3개·발견 6건 |
| `old` 태그 자식 | 1.0.0 자식만 선택, 구성요소 3개·발견 12건 |
| 중첩 미분석 자식 | 선택 3개·미분석 1개·불완전 커버리지. 기존 합계에 거짓 0건 성공을 더하지 않음 |
| 비활성 자식 | 전체 하위 모드에서 제외, 분석된 자식 2개 선택 |
| 사내 DB 초안 | 분석 영향·재분석 접수 없음 |
| 사내 DB 게시 | `1.0.0 <= version < 2.0.0` 영향 회차 1개만 재분석. 내부 ID 1건 추가, 수정 버전 2.0.0 표시 |
| 고정 버전 | 2.0.0 자식에서 사내 취약점 미검출 |
| 정책 | 실제 재분석에서 사내 ID 대상 High 차단 위반 발생 |
| 집계 갱신 | 취약점 18 → 19건, 고유 ID 13 → 14개. 철회 재분석 후 원래 합계로 복귀 |
| CVE 별칭·VEX | 같은 패키지의 공개 CVE와 CVE 별칭을 가진 사내 ID를 각각 검토 접수. 사내 ID 유지와 정확 ID 우선 선택 확인 |
| 변경 충돌·증거 | 이전 작성 리비전으로 수정하면 HTTP 409. 초안·게시·철회 이력과 과거 분석 문서·DB 해시 일치 |

최종 Docker API 검증 **23개 항목 통과**. 전체 8개 서비스를 재시작한 뒤 작성 이력과 Collection 합계가
동일함을 확인했습니다. 백엔드 **594개 테스트 통과**, 웹 **84개 테스트 통과**, typecheck·build 통과,
lint 오류 0건(기존 `onSync` 의존성 경고 1건)입니다. 변경 Python 파일 컴파일과 diff 공백 검사도 통과했습니다.

검증 스크립트는 자격증명을 개인 `.env`에서 읽고 보고서에 기록하지 않습니다. 실행 후
검증용 정책 변경을 복원하며 샘플 이력은 확인할 수 있도록 보존합니다.

```bash
DOCKER_DEFAULT_PLATFORM=linux/amd64 docker compose --env-file runtime/native-verification-20261017/.env build portal-api portal-worker portal-web
DOCKER_DEFAULT_PLATFORM=linux/amd64 docker compose --env-file runtime/native-verification-20261017/.env up -d
python3 scripts/verify-collection-private-runtime.py \
  --env-file runtime/native-verification-20261017/.env \
  --output output/collection-private-runtime-20261018/final-report.json --restart
```

## 실제 화면 확인

Chrome/Playwright로 `http://127.0.0.1:18088`의 실제 gateway 화면을 검증했습니다.
Browser 플러그인이 제공되지 않아 설치된 Playwright를 사용했습니다.

| 검사 | 결과 |
| --- | --- |
| 페이지 식별·내용·오류 오버레이 | KODA 제목과 실제 설정 내용 표시, 빈 화면·프레임워크 오류 없음 |
| 사내 DB 작성 | 쉼표를 직접 입력해 CWE 2개·별칭 2개·영향 버전 2개를 저장하고 실제 API 응답과 일치 |
| 게시·수정·철회·이력 | 버튼 조작으로 상태·리비전 변경, 식별자 변경 방지, 새로고침 후 보존 |
| Collection | 실제 자식 지표 조회, 최신 자식 모드로 저장 후 선택 1개 확인, 전체 하위 모드 복원 |
| 반응형·브라우저 상태 | 1440×1000 / 390×844, 문서 가로 넘침 없음. 콘솔/페이지 오류 0, 예상하지 않은 HTTP 오류 0 |

브라우저 검증 **10개 항목 통과**. 등록 폼·사내 DB 목록·Collection 지표·모바일 화면을
스크린샷으로 확인했습니다. 다중 영향 패키지의 첫 행을 삭제했을 때 다른 행의 버전 입력값을
잘못 보존하지 않도록 안정적인 행 키와 회귀 테스트도 추가했습니다.
별도 보관한 보고서는 `output/collection-private-runtime-20261018/final-report.json`과
로컬 `/tmp/koda-collection-private-ui-report.json`이며 자격증명·샘플 결과는 Git에 포함하지 않습니다.

## 지원 범위

사내 DB 범위는 Maven 정렬과 정식 `x.y.z` SemVer를 지원합니다. 다른 표기/생태계는 정확 버전
목록을 사용합니다. 다른 분석기의 전체 발견 집합이나 모든 버전 범위 문법을 재현한다는 뜻은
아닙니다. Collection 취약점은 VEX 적용 후 발생 건수이며 구성요소는 프로젝트별 건수입니다.
포트폴리오 전역 고유 패키지 탐색과는 구분합니다. 추가 분석기·사설 저장소 수집·전용 전송기·
OIDC/팀 ACL 등 남은 항목은 [미구현·제한 표](native-parity-audit-ko.md)에 유지했습니다.
운영 부하, 실제 조직 LDAP, Windows 설치와 폐쇄망 복원은 이번 샘플 검증 밖입니다.
