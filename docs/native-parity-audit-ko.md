# 자체 분석 기능의 지원 범위와 제한

KODA SBOM Tracker는 Grype·로컬 NVD/KEV·반입 EPSS와 자체 정책·검토·SSVC 기능을 사용합니다. 분석 결과의 기준일과 데이터 출처, 미분석·오래된 근거를 함께 확인합니다.

| 영역 | 제공 범위와 제한 |
| --- | --- |
| 취약점 분석 | Grype와 로컬 CPE 보완, 사내 취약점 DB. 다른 제품별 추가 분석기 직접 연동은 제공하지 않음 |
| 패키지 정보 | 공개 npm·PyPI·Maven·NuGet·Go·Cargo 및 오프라인 캐시. 사설 저장소 계정과 추가 생태계 수집은 별도 |
| 정책 | 자체 CEL·심각도·라이선스·프로젝트 범위·메타데이터 조건. 입력 부재·평가 실패를 통과로 처리하지 않음 |
| 프로젝트·Collection | 자체 카탈로그의 계층·태그·최신 범위와 집계. 외부 제품의 프로젝트·정책 자동 이관과 주기 동기화는 제공하지 않음 |
| 검토·대응 | 독립 승인형 VEX, 검토 이력, SSVC 근거 및 대응 이력. 반입한 공급자 문서는 자동 억제·자동 결정을 하지 않음 |
| 내보내기 | 원본 SBOM, CycloneDX VEX, 감사 CSV. 별도 제품의 전용 export 형식은 제공하지 않음 |
| 인증·알림 | 로컬/LDAP·역할·서비스 토큰, 보관함·서명 Webhook. OIDC·조직별 프로젝트 ACL·메신저 전용 전송기는 별도 |

실제 LDAP, Windows 설치, 폐쇄망 복원과 운영 규모 부하는 대상 환경에서 검증해야 합니다. 로컬·샘플 Docker 검증을 해당 환경의 인수 완료로 간주하지 않습니다.
