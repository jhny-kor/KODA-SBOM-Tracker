# 자체 운영 Docker 첫 인수 기록 — 2026-10-18

이 문서는 첫 인수 당시의 기록입니다. 아래 제한 중 고급 정책·동적 프로젝트 범위·Maven/Go 거리는
후속 구현으로 보완했습니다. 현재 결과는 [고급 기능 후속 인수](verification-complete-20261018-ko.md)를 참조하세요.

검증 대상은 격리된 Compose 프로젝트 `koda-native-verify-20261017`입니다.
실제 Grype 실행 파일·DB, PostgreSQL, 공식 저장소 HTTPS 응답과 실제 원본 API 서버를
사용했습니다. 원본은 별도의 테스트 데이터로 구성한 5.0.3 서버이며, 사용자의 운영 서버
데이터를 실제 이관한 기록은 아닙니다. 운영 원본의 주소·읽기 키 또는 export는 별도로 필요합니다.

수집기에만 연결했습니다.

## 이관 증거

원본 프로젝트 1개, 구성요소 2개, 정책 3개, 취약점 발견 2개와 검토 2개를 수집했습니다.
ALL/ANY 조건과 FAIL/WARN/INFO 동작을 KODA에서 평가하고, 원본 분석은
`legacy-import` 리비전으로 보존했습니다. 검토는 기본 미승인 상태로 가져왔습니다.
반복 적용은 같은 결과를 반환하며 회차·검토를 중복 생성하지 않았습니다.
그 후 같은 SBOM을 현재 Grype DB로 재분석해 새 리비전을 생성하고 원본 리비전도 유지했습니다.

원본에 저장된 정책 위반 기록과 KODA가 변환 규칙으로 새로 평가한 결과는 별도 증거입니다.
원본의 지연된 위반 집계 건수가 KODA의 새 평가와 항상 같다고 주장하지 않습니다.
모든 외부 분석기의 탐지 범위·지표 계산식을 동일하게 재현했다는 검증도 아닙니다.

## 재현과 증거 위치

실행 환경의 `output/migration-runtime-20261018/`에 새 기능·기존 기능·주기 작업·재기동·화면
검사 JSON을 보관했습니다. 원본 export와 인증 파일은 별도 비공개 `runtime/`에 보관하고
저장소에는 포함하지 않았습니다. 이 디렉터리들은 배포 소스에 포함하지 않습니다.

반복 검증 스크립트는 다음과 같습니다. 격리된 테스트 스택에서만 사용합니다.

```bash
python scripts/verify-native-runtime.py --env-file <테스트.env> --base-url <KODA주소> --output-dir <결과폴더>
python scripts/verify-advanced-runtime.py --env-file <테스트.env> --base-url <KODA주소> --output <결과.json>
python scripts/verify-migration-runtime.py --env-file <테스트.env> --base-url <KODA주소> --source-auth-file <비공개원본인증.json> --source-project <테스트프로젝트UUID> --api-container <테스트API컨테이너> --output <결과.json>
```

이관 검증 스크립트의 원본 인증 파일은 `baseUrl`, `apiKey`를 포함하며 권한 `0600`으로
관리합니다. 해당 스크립트는 검증 중 테스트 정책을 일시 적용한 뒤 원래 정책으로 복구합니다.
