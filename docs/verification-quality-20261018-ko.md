# SBOM 품질 진단 실제 검증 — 2026-10-18

## 변경과 인수 기준

품질 진단을 분석 흐름 앞에 추가했습니다. 기본 경고 모드가 기존 업로드를 막지 않으며,
프로젝트별 강제 기준과 CEL 정책은 CI 게이트에서 차단되는지를 확인합니다.
Grype·원본 SBOM·기존 분석/품질 리비전은 유지합니다. 환경은 Mac의 격리 Docker 스택
`koda-native-verify-20261017`, gateway `http://127.0.0.1:18088`입니다.
자격증명·실행 결과·스크린샷·테스트 자료는 Git에 포함하지 않습니다.

## 실제 API·worker·Grype·CEL·CI

`scripts/verify-quality-runtime.py`의 **18개 검증 항목 통과**입니다. 모의 Grype나 가짜
CEL 응답을 사용하지 않았으며 실제 worker와 기존 Grype DB, 격리 CEL 프로세스를 사용했습니다.

| 확인 | 관측 결과 |
| --- | --- |
| 자체 기동 | Dependency-Track 비활성 상태에서 실행 |
| 중첩 진단 | 구성요소 2개 중 식별자 누락 1개 → 0.5, 정확한 원본 경로·개선 방법 제공 |
| 페이지·필터 | 서버에서 1개씩 조회, 규칙별 필터로 자식 진단 선택 |
| 경고 도입 | 문제 SBOM도 기본/프로젝트 경고 모드에서 품질만으로 CI 차단하지 않음 |
| 강제 기준 | 같은 프로젝트를 강제 모드로 바꾸면 자동 재분석 후 품질 fail·CI blocked |
| 증거 보존 | 기준 변경 전 품질 리비전 JSON이 그대로 유지됨 |
| 원본·내보내기 | 원본 SHA 검증 근거, JSON과 CSV의 끊어진 참조 진단 확인 |
| 수정본 | 다음 회차의 오류·경고 0, 강제 기준 통과와 변화량 개선 |
| XML | 동등 JSON/XML의 품질 요약 전체 일치 |
| 프로젝트 격리 | 별도 기준이 없는 다른 릴리스에는 강제 기준이 누출되지 않음 |
| CI 명령 | 강제 기준 미달은 종료 1, 수정본은 종료 0 |
| CEL | 실제 미리보기 일치 1건, 품질 오류 표현식이 정책 위반 생성·CI 종료 1 |

검증 스크립트는 해당 샘플 서비스에만 적용하는 CEL 규칙을 잠시 추가하며 원래 정책을
새 버전으로 복원하고 임시 CI 토큰을 폐기합니다. 원래 정책을 복원해도 버전은 증가하므로
그 이전 분석을 CI에 다시 사용하려면 재분석해야 합니다.

```bash
python3 scripts/verify-quality-runtime.py \
  --env-file runtime/native-verification-20261017/.env \
  --output-dir output/quality-20261018
```

최종 배포 이미지에서도 같은 18개 항목을 다시 통과했습니다. 결과는 로컬
`output/quality-20261018/runtime-report.json`과 `final/runtime-report.json`에 보관했습니다.
운영 인스턴스가 아닌 격리된 샘플 스택에서 실행합니다.

통과, lint 오류 0건이며 기존 `App.tsx`의 `onSync` 의존성 경고 1건은 남아 있습니다.
백엔드에는 기존 FastAPI/LDAP 의존성의 deprecation 경고가 있습니다.

추가 읽기 검토에서 발견한 아래 사례도 수정하고 회귀 검증했습니다.
