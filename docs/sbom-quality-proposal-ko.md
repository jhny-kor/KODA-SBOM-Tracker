# SBOM 품질 진단 도입 제안

상태: **설계 제안, 아직 미구현**. 현재 스키마 검증·라이선스 누락 정책·패키지 식별 상태를
확장하되, 취약점 위험과 SBOM 자료의 품질을 별도 결과로 제공합니다. 취약점 0건은 자료가
잘 채워졌다는 뜻이 아닙니다. 점수는 KODA 운영 프로필의 값이며 공식 표준 인증 점수가 아닙니다.

## 1차 도입: 원인과 분모가 있는 진단

이번 수정의 공통 중첩 순회·PURL 정규화 결과를 그대로 사용합니다. 각 항목은 원본 경로,
`bom-ref`, 규칙 ID, 심각도, 관측값/기대값, 개선 방법을 기록합니다. 이름·버전·PURL을
임의로 채워 통과시키지 않습니다.

| 영역 | 초기 검사 | 권장 초기 처리 |
| --- | --- | --- |
| 식별 | 이름/버전, PURL 또는 CPE/SWID, 식별자 구문·버전 모순, 중복 식별 | 모순·모호한 중복은 오류, 식별자 누락은 경고 |
| 구조·관계 | 중첩 범위 일치, 중복 bom-ref, 존재하지 않는 의존성 ref, 루트 연결, 그래프 순환 | 중복·끊어진 참조는 오류. 순환은 허용 생태계가 있어 경고/프로필 판정 |
| 라이선스 | 식별 가능한 ID/표현식, NOASSERTION·미상, 표현식 문법 | 누락·검토 필요를 표시. 스키마/정책 지원과 법률상 호환성 인증을 구분 |
| 무결성 | 해시 알고리즘·값 형식, 중복/상충 해시, 선택적 artifact digest 연결 | 잘못된 형식·상충은 오류, 해시 없음은 경고. 소스 SBOM에 해시가 있다는 사실과 실제 파일 대조를 구분 |
| 출처·시각 | 공급자, 생성 도구/작성자, 생성 시각·문서 식별자, 버전·신선도 | 누락·오래된 자료를 경고하고 확인 가능한 근거 표시 |

분모는 중첩을 포함한 전체 구성요소이며 적용 불가/미확인/누락을 구분합니다. 그래프가
없을 때 의존성 연결률을 100%로 표시하지 않습니다. 품질 평가 실패도 점수 0이나 통과로
표시하지 않고 `failed`로 남깁니다. 부적절한 문자열이나 스키마 오류는 기존 반입 검증에서
거부하고, 품질 검사는 그 다음에 수행합니다.

## 화면·저장·API

회차 상세에 **SBOM 품질** 탭을 추가합니다. 요약(완전성·오류·경고·미확인), 누락 항목별
건수/비율, 원본 위치를 가진 구성요소 목록, 이전 회차 대비 개선/악화를 제공합니다.
CSV/JSON 다운로드와 필드·규칙·심각도별 서버 페이지 조회를 제공합니다.

불변 `SbomQualityRevision`에 회차·원본 SHA-256·정규화 버전·진단 엔진 버전·프로필 버전·
실행 시각·통계·상태를 저장하고, 대량 이슈는 별도 행 테이블로 페이지 조회합니다.
재진단은 새 리비전을 추가하며 이전 보고서를 덮어쓰지 않습니다.
제안 API는 `/api/v1/sbom-runs/{id}/quality-revisions`, `/quality-issues`와 실행/내보내기입니다.
기존 서비스 범위·읽기 권한을 재사용하고 프로필 수정 권한을 별도로 제어합니다.

흐름은 **스키마 검증 → 정규화 → 품질 진단 → Grype·정책 평가 → 결과 제공**입니다.
품질 진단 자체는 네트워크 접속 없이 수행해 폐쇄망에서 재현 가능하게 유지합니다.

## 2차 도입: 선택적 점수·프로필·CI 정책

점수보다 이슈와 근거를 먼저 출시합니다. 이후 조직별 프로필에서 식별 30·관계 20·라이선스
20·출처 20·무결성 10의 예시 가중치를 조절하게 합니다. 적용 불가 항목은 이유를 표시하고
분모에서 제외하며 미확인·평가 실패를 적용 불가로 바꾸지 않습니다.
중복 bom-ref 등 핵심 오류는 평균 점수가 높아도 품질 통과로 가리지 않습니다.

처음에는 경고 모드로 운영하며 실제 SBOM 자료로 오탐과 누락을 조정합니다. 다음 단계에서
프로젝트별 강제 프로필과 CEL의 `sbomQuality.errorCount`, `missingIdentityRatio`,
`unresolvedRefCount` 등을 추가합니다. CI 호출기는 분석·품질·정책 완료를 확인하고 실패·
데이터 부족을 명시적으로 차단합니다. 현재의 VEX 승인으로 품질 누락까지 억제하지 않습니다.

인수 기준은 JSON/XML의 동등한 결과, 중첩/범위 패키지/동일명·다른버전/깨진참조 샘플,
프로필 변경 시 과거 결과 보존, 대용량 페이지 조회, 평가 실패의 명확한 표시입니다.

참고: [CycloneDX SBOM](https://cyclonedx.org/capabilities/sbom/),
[공식 가이드](https://cyclonedx.org/guides/). 구체적인 필수 항목·차단 기준·가중치는
조직의 반입 기준과 공급업체 SBOM 특성에 맞춰 정해야 합니다.
