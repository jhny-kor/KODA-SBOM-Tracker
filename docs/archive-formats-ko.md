# 취약점 자료와 SBOM 압축 형식

지원 형식은 **ZIP, TAR.GZ(TGZ), TAR, 7Z**입니다. RAR은 생성·업로드 대상에서 제외합니다. 이번 변경은 취약점 자료 생성·반입 및 SBOM 업로드에 적용하며, Linux 설치·업데이트 패키지의 형식과 절차는 기존과 같습니다.

## 생성 형식 선택

인터넷 연결이 가능한 자료 수집 PC에서 기존 `scripts/collect-unified-data.py` 명령의 `--format`으로 형식을 지정합니다. 생략하면 출력 파일의 확장자로 판단합니다. 형식과 확장자가 다르면 생성하지 않습니다.

```bash
python3 scripts/collect-unified-data.py \
  --source /data/approved-sources \
  --signing-key /secure/data-signing-private.pem \
  --version import-20261102 \
  --data-date 2026-11-02 \
  --grype-date 2026-11-01 \
  --format zip \
  --output /exports/unified-20261102.zip
```

위 경로와 날짜는 예시입니다. 원본 자료의 기준일과 실제 Grype DB 생성일을 사용합니다. `--format` 값은 `zip`, `tar`, `tar.gz`, `7z` 중에서 선택합니다. 예를 들어 `--format 7z --output /exports/unified-20261102.7z`로 바꿀 수 있습니다. 기존 개별 자료 생성기 `scripts/build-data-update.py`에도 같은 옵션을 지원합니다. 통합 관리 환경에는 서명된 통합 자료를 반입합니다.

서명은 압축 내부의 기존 `manifest.sha256`를 대상으로 합니다. 형식이 달라도 파일별 해시·등록 공개키 검증은 유지되며, 개인 서명키는 압축에 포함하지 않습니다. 생성된 파일은 완료 후 원자적으로 게시하고 기존 동명의 파일을 덮어쓰지 않습니다.

ZIP·TAR 계열에는 Python 표준 라이브러리를 사용합니다. 7Z에는 시스템 `libarchive`가 필요하며, 새 Linux API/작업자 이미지에 해당 런타임을 포함합니다. 별도 수집 PC에서 7Z를 생성할 때도 `libarchive`를 설치해야 합니다. 자료가 큰 경우 원본·작업용 복사본 외에 최종 출력과 7Z 임시 압축 파일의 공간을 함께 확보합니다.

## 업로드

- **취약점 자료:** 설정 → 취약점 데이터 → 공개 참조 자료에서 통합 압축파일을 업로드합니다. 최대 2GiB이며 기존과 같이 업로드·검증 후 **별도로 적용**해야 활성화됩니다. 서명 누락·변조·미등록 키는 거부합니다. 해제 제한은 파일당 4GiB, 전체 12GiB, 최대 100,000개 항목을 유지합니다.
- **SBOM:** JSON/XML/CSV 문서를 직접 올리거나, 압축 안에 지원 SBOM 문서 파일을 **정확히 한 개** 넣어 업로드합니다. 폴더는 허용하지만 README·다른 문서·중첩 압축을 함께 넣을 수 없습니다. CycloneDX 1.4~1.7 JSON/XML, SPDX 2.3 JSON, KODA가 내보내는 UTF-8 NIS-SBOM 1.0 20열 CSV를 지원합니다. 원본 업로드와 압축 해제 한도는 각각 5 GiB입니다. 큰 UTF-8 JSON은 파싱 전에 문자열 밖 공백을 스트리밍으로 줄입니다. 이후에도 128 MiB를 넘는 CycloneDX 1.6/1.7 UTF-8 JSON은 구성요소와 의존 관계를 항목별로 나눠 저장하고 분석합니다. 다른 형식은 일반 처리 경로의 128 MiB 한도를 따릅니다. 운영 한도와 구성요소·구조 제한은 [대용량 SBOM 처리 안내](troubleshooting-ko.md)를 확인하세요.
- **원본·이력:** SBOM 압축 원본의 바이트·해시·파일명·미디어 유형을 보관합니다. 임시로 해제한 문서로 품질 검사와 분석을 수행하고, 임시 파일은 정상·실패 경로에서 정리합니다. 원본 내려받기는 업로드한 압축 원본을 반환합니다. 기존 JSON/XML 자료와 재분석 이력을 유지합니다.

서버는 확장자 대신 실제 내용을 확인합니다. 암호화, 분할 압축, 미지원 압축 방식, 손상된 파일, 경로 탈출, 링크·특수 파일, 중복 경로, 한도 초과는 거부합니다. 해제는 별도 프로세스에서 수행하며 Linux에서 메모리·CPU·파일 크기와 처리 시간을 제한합니다. 작은 `/tmp` 메모리 디스크를 넘는 SBOM 문서는 기존 artifact 저장소의 전용 임시 디렉터리에서 처리합니다.

로컬 브라우저 단독 미리보기는 기존 JSON/XML 전용입니다. 실제 압축 처리에는 새 API·작업자와 웹 빌드를 사용해야 합니다.

## 검증 결과와 배포 상태

2026-11-02에 백엔드 전체 1,016개와 별도 회귀 9개, 프런트엔드 192개 검사를 통과했습니다. 백엔드 20개는 환경 조건으로 건너뛰었고 기존 macOS PowerShell 환경에 맞지 않는 검사 1개는 제외했습니다. 타입·프런트 빌드·범위 lint·Python 문법·diff 검사를 통과했습니다.

실제 Linux 이미지에서 20개 런타임 검사, 기본·더 엄격한 상속 자원 제한, 120MiB SBOM 처리와 손상된 대형 메타데이터의 제한된 오류 처리를 확인했습니다. `/app` 및 설치된 Python 모듈 66개가 현재 소스와 모두 일치했습니다. 서명·별도 적용 흐름은 별도 API 회귀에서 네 형식 모두 검사했습니다. 브라우저 화면 검증은 합성 API를 사용했고 백엔드 압축 처리 검증과 구분했습니다.

이번 변경은 현재 소스와 검증용 Linux 이미지에 반영했습니다. 기존 2026-10-29 서명 설치 압축파일은 변경하지 않았습니다. 운영 반영에는 수정된 API·작업자·웹 산출물의 빌드·배포가 필요합니다. 대용량 multipart 전송의 선행 임시 저장은 서버 임시 디스크의 가용 공간 조건을 따릅니다.
