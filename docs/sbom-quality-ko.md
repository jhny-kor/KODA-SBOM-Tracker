# SBOM 품질 진단과 프로젝트별 기준

SBOM 품질은 취약점 개수와 별도로 평가합니다. 구성요소 식별 정보·의존성 관계·라이선스·
해시·출처가 빠졌거나 모순되는 위치와 개선 방법을 제공합니다. Grype와 기존 정책·VEX는
계속 사용하며, VEX의 영향 없음 승인은 품질 누락을 숨기지 않습니다.

## 진단 범위

| 영역 | 검사와 표시 |
| --- | --- |
| 식별 | 이름·버전 누락, PURL/CPE/SWID 기본 구문, PURL 버전 모순, 같은 좌표·버전 중복. 다른 버전의 공존은 중복으로 처리하지 않음 |
| 관계 | 중복 bom-ref, 끊어진 참조, 루트와 분리된 구성요소, 순환, 그래프 누락. 순환은 경고이며 생태계에 따라 허용 가능 |
| 라이선스 | 누락·미상, SPDX 표현식 문법. 법률상 호환성 인증이나 명칭의 진위 검증은 아님 |
| 무결성 | 해시 알고리즘·16진수 길이·중복·상충. SBOM에 선언된 값을 검사하며 실제 패키지 파일과의 대조는 아님 |
| 출처·신선도 | 생성 시각·미래 시각·기준 기간 초과, 생성 도구·작성자·공급자·문서 식별자 누락 |

`components`와 그 하위 중첩 구성요소를 분모에 포함합니다. `metadata.component`의
애플리케이션 루트는 별도로 참조 연결·출처 검사에 사용하며 패키지 분모에는 넣지 않습니다. 빈 SBOM의 누락 비율은 0%가 아니라 적용 불가이며,
빈 구성요소 목록 자체는 오류입니다. 잘못된 식별자만 있으면 식별자 누락에도 포함합니다.
진단 실패는 건수 0·통과가 아니라 `failed`와 원인을 저장합니다. JSON/XML 원본이 있으면
SHA-256을 검증한 뒤 읽습니다. 원본 없는 기존 JSON은 저장된 정규화 자료로 진단하되
근거를 표시하고 CI 통과는 허용하지 않습니다. 기존 XML은 원본이 없으면 실패합니다.

회차 상세의 **SBOM 품질**에서 결과·원본 경로·bom-ref·관측값·기대값·개선 방법,
이력 선택, 오류/경고·규칙 필터, 페이지 조회, CSV/JSON 다운로드를 제공합니다.
진단 경로는 CycloneDX JSON 형태이며 XML도 같은 구조로 정규화한 경로를 표시합니다.
재진단은 새 리비전을 만들며 원본·과거 분석과 품질 결과를 덮어쓰지 않습니다.
이전 품질 리비전이 없으면 같은 릴리스의 이전 회차와 오류·경고 변화량을 비교합니다.
기준과 엔진이 다를 수 있으므로 변화량만으로 품질 개선을 단정하지 않습니다.
점수는 아직 적용하지 않으며 `score=null`입니다.

## 프로젝트별 기준

회차 상세에서 **프로젝트별 품질 기준**을 선택합니다. 공통 기준 또는 네이티브 프로젝트
카탈로그의 내부 프로젝트 ID를 지정해 이름·모드·허용 오류/경고 수·식별자 누락 비율·
끊어진 참조 수·최대 자료 나이(일)를 설정합니다. 경고 수 미지정은 별도 상한 없음입니다.
신선도 초과는 경고이므로 이를 강제하려면 허용 경고 수도 설정해야 합니다.

| 모드 | 기준 미달 시 |
| --- | --- |
| 경고 `warn` (기본) | 품질 경고를 제공하며 품질 기준만으로 CI를 막지 않음 |
| 강제 `enforce` | 허용치를 초과하면 품질 `fail`; CI 게이트 차단 |

명시적으로 연결된 프로젝트를 우선하고, 없으면 서비스·환경·릴리스가 유일하게 일치하는
프로젝트 기준을 적용합니다. 프로젝트에 별도 기준이 없으면 공통 기준을 상속합니다.
여러 프로젝트가 같은 회차 후보이고 별도 기준이 있어 소유가 모호하면 진단을 실패시켜
엉뚱한 기준을 선택하지 않습니다. 먼저 카탈로그에서 회차를 명시적으로 연결하세요.
부모의 기준을 자식에 자동 상속하거나 태그로 품질 기준을 배정하는 기능은 포함하지 않습니다.

수정에는 `policies.manage`, 조회에는 `policies.view` 또는 `policies.manage`가 필요합니다.
기준은 버전별로 보존하고 동시 수정은 409로 거절합니다. 기준 변경 시 영향받는 비보관
회차의 재분석을 접수합니다. 결과에 평가 당시 기준·엔진·원본 SHA와 분석이 사용한
품질 리비전 ID를 함께 보관합니다. 신규/재분석은 자동 진단하며 기존 회차는 재분석 또는
품질 재진단으로 결과를 생성합니다. 보관 회차는 기존 결과만 조회할 수 있습니다.

## CEL은 무엇인가

CEL(Common Expression Language)은 정해진 자료에 참/거짓 조건을 쓰는 정책 표현식입니다.
KODA에서는 참이 되면 해당 정책의 위반으로 기록합니다. 다음은 프로젝트 전체를 한 번
평가해 품질 오류 또는 평가 실패를 정책 위반으로 만드는 예입니다.

```cel
sbomQuality.state != "completed" || sbomQuality.errorCount > 0
```

식별자 누락 비율 5% 초과를 막으려면 다음처럼 평가 상태·적용 가능 여부부터 확인합니다.

```cel
sbomQuality.state != "completed" ||
  (sbomQuality.missingIdentityRatio != null && sbomQuality.missingIdentityRatio > 0.05)
```

대상은 `project`, 종류는 `cel`, 동작은 `fail`로 설정합니다. 기존 서비스·환경·릴리스·
프로젝트 범위 조건과 함께 사용할 수 있습니다. 분석 정책은 당시 품질 스냅샷을 사용하고,
미리보기는 현재 저장된 최신 품질을 사용합니다. 표현식은 격리된 기존 CEL 런타임에서
실행하며 오류를 통과로 처리하지 않습니다. CEL 없이 품질 프로필만으로도 강제할 수 있습니다.

## CI 차단은 무엇인가

CI는 코드 변경 후 빌드·검사·배포를 자동 실행하는 파이프라인입니다. KODA가 검사 결과를
반환하고, CI 단계가 통과 여부에 따라 종료 코드를 내게 연결하면 다음 배포를 멈출 수 있습니다.
이번 구현은 게이트 API와 실행기를 제공하며 외부 GitHub/GitLab의 보호 규칙을 자동 변경하지 않습니다.

```bash
# 업로드 응답의 runId 사용. 토큰은 CI의 비밀 변수에서 공급합니다.
export KODA_TRACKER_URL=https://koda.example.internal
export KODA_TRACKER_TOKEN="$CI_KODA_TOKEN"
python3 scripts/check-sbom-gate.py "$RUN_ID" --timeout 600
# 이 명령이 성공한 뒤에만 배포 단계를 실행하도록 CI에 연결합니다.
```

`GET /api/v1/sbom-runs/{id}/gate`는 `pass|pending|blocked`, `allowed`, 원인 코드와 근거 ID를
제공합니다. 실행기는 통과 시 0, 차단 시 1, 시간 초과·통신·인증 오류 시 2로 종료합니다.
진행 중에는 기다립니다. 분석·정책 실패, 자료 불완전, 정책 위반, 강제 품질 기준 초과,
기준 변경 뒤 구형 결과, 엔진 변경, 원본 확인 전, 품질/분석 리비전 불일치, 보관 회차를 차단합니다.
품질만 수동 재진단한 뒤에는 분석도 실행해야 같은 근거로 CI를 통과할 수 있습니다.
게이트는 마지막 평가 시점의 결과이며 데이터 갱신과 무관하게 최신 취약점 부재를 보증하지 않습니다.

서비스 토큰은 자기 서비스 범위만 조회할 수 있고, 무범위 토큰은 자신이 올린 회차만
조회할 수 있습니다. 이 명령을 무시하거나 CI의 오류 무시 옵션을 켜면 배포는 차단되지 않습니다.

## API

| API | 용도 |
| --- | --- |
| `GET/POST /api/v1/sbom-runs/{id}/quality-revisions` | 이력 페이지 조회 / 수동 재진단 |
| `GET /api/v1/sbom-runs/{id}/quality-issues` | `revisionId`, `ruleId`, `severity`, `page`, `size`로 이슈 조회 |
| `GET /api/v1/sbom-runs/{id}/quality-export` | `revisionId`, `format=json|csv`로 내보내기 |
| `GET/PUT /api/v1/quality-profiles?projectId=...` | 기준 조회 / `expectedVersion`으로 버전 확인 후 저장 |
| `GET /api/v1/sbom-runs/{id}/gate` | 현재 근거로 CI 허용 여부 조회 |
